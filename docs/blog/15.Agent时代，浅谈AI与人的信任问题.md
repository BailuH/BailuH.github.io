大家端午安康！这里是备考期末版的青麓。

这几天我通过北京市创的资金租了一台小的云服务器，尝试将我的市创项目（一个与AI模拟法庭有关的Web网站）搬到云上。借此机会也是给我这个没见过市面的大学生看了一下真正的“生产环境”是什么样的。

![image.png](https://bailu-1382509292.cos.ap-beijing.myqcloud.com/obsidian/20260618112459680.png)

我采用的方法是在云服务器上使用Kimi Code，让它来辅助我完成一些任务。我首先让它帮我查看了一下当前的系统环境。

![image.png](https://bailu-1382509292.cos.ap-beijing.myqcloud.com/obsidian/20260618112614142.png)

后来又做了一系列的操作，比如安装Docker、配置Github并拉取我的项目（过程中又遇到了一些内网穿透的问题，通过给我的云主机配置本地代理最终解决）之类的，兴致勃勃地探索了一下午终于搞定。出于好玩，硬要说的话，也抱着看看哪个部分值得提炼为 *Skills* 的心理，我开始重新浏览一遍我和Kimi的对话。我突然发现一个挺有意思的对话，启发了我的思考——

![image.png](https://bailu-1382509292.cos.ap-beijing.myqcloud.com/obsidian/20260618113455616.png)

事情是这样的，我原本直接想让Kimi自己去拉取我的仓库（在此之前我已经 **手动** 配置好了我的SSH密钥、用户名、邮箱），因为网络问题而超时了。然后Kimi则产生了诸如浅克隆的想法，使用code agent经验丰富的朋友就知道，这显然是网络代理的问题，浅克隆什么的肯定解决不了什么问题，这个时候如果不人工干预一下就越走越远了。于是我果断中断了对话，自己去研究网络代理的解决方法去了，让Kimi不要再管克隆仓库的问题了。

很多朋友可能在冲浪的时候可能看过很多关于AI删库跑路并诚恳道歉的笑话。事实中现在的code agent对于删除操作权限还是比较谨慎的，以Kimi为例，权限最低的时候甚至连读文件都需要用户批准，这样的设计有的时候虽然很繁琐（毕竟很多人用Coding Agent就抱着一种炼丹的心态，输入即结果），但确是相当必要的。我几乎很少选择 “*Approve During this session*”，倒不是担心出现删库跑路笑话，而是AI很多时候倾向于逃避问题根源，并在此基础上进行很多没有必要的操作。

这似乎是老生常谈的问题了，这个现象早已有人指出过，甚至做成了梗图😀
但我想指出的是，这实际上是一个**信任问题**，并且这个信任问题可能远比我们想象的要复杂，甚至会成为**制约未来各大AI厂商推动模型商业价值转化**的关键。以我这个简单的让AI拉取仓库并克隆到我的云服务器上的任务为例，我已经走了一条相对最省时的时间线，即及时中断并人工（排查并）处理问题。

![image.png](https://bailu-1382509292.cos.ap-beijing.myqcloud.com/obsidian/20260618115414289.png)

问题的关键在于，Kimi在这里“感知”不到自己正处在一个云服务器的环境中，对于Kimi来说，**它的世界就是一个与用户的会话，自身的庞大参数是应对这个对话输入的“触发开关”**。不妨想象高尔顿板实验中反弹小球的柱子，如果小球下落的位置不变，不论上方柱子的数量再怎么增加，对于最终的结果（正态分布）不会有什么影响。

![image.png](https://bailu-1382509292.cos.ap-beijing.myqcloud.com/obsidian/20260618121024897.png)

所以这就是为什么我不相信AI可以自己修复这个问题，即使在这个会话中我曾和他说过现在处在一个云主机的环境。这里的“不信任”在于，不论你强调多少次你项目的独特要求，AI始终会在注意力的不断漂移中失去对你提出指令的遵循程度。人类在面对未知的难题时会尝试先分析问题，而AI只会假模假样地分析，实际上最终还是回归到训练数据的平均线上，泛化能力欠佳。而AI能否从资本叙事中走向实处，走向生活与应用，进而推动生产力的又一次革命与飞跃（或是倒退）犹未可知。

回顾过去一年最成功的AI Agent产品，无疑是coding agent。Claude Code的成功让无数的厂商推出了自己的“Code”（Kimi Code、WorkBuddy、Qwen Code、OpenCode、codex...），很多人误以为成功的秘诀是终端式的应用形态、是Geek风尚，毕竟客观上基于终端的 coding agent 确实很大程度上挤压了如Cursor这样基于IDE的coding agent，但这实在是**倒因为果**且**违反直觉**的。还是那句话，AI商业化的关键在于取得用户的信任，让用户能够开发其主观能动性，将AI融入到自己**原有的**工作流，而不是为了引入AI编程工具而改变原有的工作方式，实现真正的降本增效。

如果读者还是比较疑惑为什么人与AI之间的信任如此重要，不妨关注一下 Kimi 最近推出的 webbridge 浏览器插件，能够让Kimi Agent直接调用用户的浏览器进行搜索、截图、思考与行动。一开始看到这个功能的时候，我其实是有些不解的，因为联网搜索这个功能很早就已经为 Kimi Agent 所支持的，何必大费周章调用用户的浏览器去检索呢？

![image.png](https://bailu-1382509292.cos.ap-beijing.myqcloud.com/obsidian/20260619163720832.png)

不过我很快就明白了，这就是 Kimi 在获取用户信任的一次小尝试。举个例子，我的浏览器由于在校园网环境之下，如果点开中国知网就可以自动登录学校图书馆的账号，进一步就可以免费访问和下载法学相关的论文，这是传统的工具调用所不能完成的。更不必说，这种直接操控浏览器的方式，相比于终端力涌动的代码行，能更加直观带给用户一种“智能感”。设想你是一个对AI抱着很谨慎的态度、担心AI对你的电脑做出任何不利之事的人，你坐在电脑前看着 Kimi 自动打开知网，在搜索栏检索相关论文并下载的场景，这和你自己去检索并没有大的出入，而你是确确实实省力了，久而久之你就会逐渐卸下防备。这就是关键——直观地让用户产生**信任感**。

![image.png](https://bailu-1382509292.cos.ap-beijing.myqcloud.com/obsidian/20260619163047369.png)

![image.png](https://bailu-1382509292.cos.ap-beijing.myqcloud.com/obsidian/20260619163550580.png)

社交媒体上关于AI的职场焦虑似乎越来越严重了，不论什么行业的人都在抱怨“AI的暴政”。不是老板要求在工作中引入AI，就是同辈渲染某某工具又提升了自己多少生产力。过去的一年我也是被AI裹挟的那部分人，始终都在学习和了解各种AI工具，说实话，**真的跟不上**！但那又怎么样呢？回首摆弄这些AI生产力工具的一年，大多数时候都是新瓶装旧酒。我不知道AI是怎么帮我查找文献的，所以我拿到AI的结果还是不得不去知网复核一遍；我不知道AI是怎么给我做PPT的，所以我拿到AI的结果还是不得不重新调整字号、动画与内容；我不知道AI是怎么帮我写的代码，因此还是要不断Debug。*我根本不相信AI，我相信它很聪明，只是它产出的结果总不是我的预期，或者说，如果我自己做我根本不会像他这样做*。既然如此，那何必强求为难彼此呢，不用AI就是最好的办法。

过去的教育总是在教导我，要顺应时代，与时俱进。但我认为还得加一个前提，就是只有当你真正理解、信任、并拥抱了新的变化，否则不是顺应时代，而是被时代所裹挟。诺贝尔经济学奖得主阿玛蒂亚·森在上个世纪就在《以自由看待发展》（_Development as Freedom_, 1999）中提出，**发展的本质不是经济增长，而是扩展人们享有的真实自由的过程**。自由既是发展的首要目的，也是发展的主要手段。自由当然也包括了工具自由，工具自由的核心在于**信任**，AI的突然出现让人类显得有些无所适从，人类历史上从未出现一个可能会产生自我意识的、不可控的工具，因此工具自由与信任问题前所未有地突出。
